Service detail

AI in our workflow

AI at every stage, an engineer at the end of each one

AI is part of how every service above is delivered — not a separate product. It reads, drafts, groups and checks so the team spends its time on engineering judgement. Nothing it produces is issued without a named engineer's review.

01Live

Input review

AI reads drawing sets, specifications and models to list systems, missing information and conflicts before modelling starts — so the query list exists on day one, not week three.

Read → Extract → Flag gaps
02Live

Modelling

AI-assisted routines generate and populate repetitive content inside the agreed template — parameters, tags, schedules, sheets and family data — while modellers focus on routing.

Template → Generate → Populate
03Live

Coordination

AI groups clashes by cause and responsible discipline, ranks them by impact and drafts the issue descriptions a coordinator confirms before they go to the team.

Detect → Group → Prioritise
04Live

QA / QC

AI-assisted checking runs standards, naming, parameter completeness and clearance rules over the whole model before every issue, and clusters failures by root cause.

Check → Cluster → Report
05Live

Quantities

Quantities extracted, classified and reconciled across revisions, with anomalies and unmeasurable elements flagged for review rather than silently counted.

Measure → Reconcile → Compare
06Live

Documentation & handover

Clash reports, issue logs, revision registers, asset registers and handover notes drafted from model data — then checked and signed by a named engineer.

Draft → Review → Sign

Handover checklist

The deliverables a project can receive, and what is agreed up front

Ten handover items from the service catalogue. Which ones apply is set in the proposal; how each one is defined is agreed before work starts.

Deliverable 01Native Revit model
Editable .RVT files for contracted scope.
  • Included: Yes, if modeling is in scope
  • Agreed at start: Confirm Revit version and worksharing handover
Deliverable 02Federated coordination model
Linked models and Navisworks files where contracted.
  • Included: Optional
  • Agreed at start: Specify model ownership and source files
Deliverable 03Drawing package
PDF drawings and agreed DWG exports.
  • Included: As contracted
  • Agreed at start: Define issue status and approval workflow
Deliverable 04Schedules and quantities
Revit schedules and Excel quantity takeoffs.
  • Included: As contracted
  • Agreed at start: Define quantity rules and exclusions
Deliverable 05Clash report
Clash matrix, issue list, screenshots and viewpoints.
  • Included: If coordination is in scope
  • Agreed at start: Define tolerances and clash rules
Deliverable 06Design documentation
Risers, schematics, sections and details.
  • Included: As contracted
  • Agreed at start: Depends on design stage and discipline
Deliverable 07Model QA/QC report
Model checks, unresolved issues and exclusions.
  • Included: Recommended
  • Agreed at start: Define QA checklist
Deliverable 08Revision register
Drawing/model versions and change records.
  • Included: Recommended
  • Agreed at start: Define naming and revision rules
Deliverable 09Exchange files
IFC, NWC, NWD or BCF where specified.
  • Included: Optional
  • Agreed at start: Confirm software compatibility
Deliverable 10Handover note
File index, scope status, assumptions and limitations.
  • Included: Recommended
  • Agreed at start: Include unresolved issues and exclusions

Service pages

Each capability in detail

Deliverables, sequence, required inputs, where automation applies and what the appointment does not include — set out per service rather than summarised.

Plumbing BIM The only discipline on the project that cannot be rerouted around a problem, because gravity is not negotiable — which makes it the one that should be routed first and almost never is. Plumbing BIM & engineering HVAC BIM The discipline that usually decides how deep the ceiling void has to be — and therefore the one whose routing decisions everything else inherits. HVAC BIM & engineering Fire protection BIM The discipline whose coordination failures are the most consequential and the most geometric — coverage is a spatial test, and a spatial test is something a rule set can actually run. Fire protection BIM & engineering Electrical BIM The discipline with the most flexible routes and the least respected space allocation — which is exactly why its coordination failures surface last and cost most. Electrical BIM & engineering BIM coordination & clash detection Clash detection produces a number. Coordination produces a decision — what actually conflicts, why, whose model has to move, and evidence that it did. BIM coordination MEP shop drawings & documentation Drawings are a view of the coordinated model, not a parallel deliverable — which is the only way a change stays one event instead of two. BIM documentation & drawings Quantity takeoff & BOQ A quantity is only as good as the rule that measured it. Ours state the rule, the source model and its version on every line. Quantity takeoff, schedules & BOQ Revit modelling & model management Most of what goes wrong in a Revit project was decided in the first week, in the template and the parameter schema, by someone who was told to start modelling. Revit modelling & model management As-built & existing-building BIM As-built means what was installed, not what was designed — and a record model is only as trustworthy as the verification behind it.
